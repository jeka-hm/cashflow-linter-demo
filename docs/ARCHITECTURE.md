# Як влаштовано «Лінтер кешфлоу»

## Три частини

```
┌────────────────────────────── браузер, сторінка CRM ──────────────────────────────┐
│  закладка → завантажувач → панель (один файл cashflow_linter.js)                    │
│     core/  — логіка: правила, звірка, зіставлення                                   │
│     ui/    — вкладки панелі                                                         │
│        │ читає й змінює записи через API самого CRM (вхід користувача)              │
└────────┼──────────────────────────────────────────────────────────────────────────┘
         │ http://127.0.0.1 (лише цей комп'ютер)
┌────────▼─────────────────────┐        ┌─────────────────────────────┐
│ «Помічник» — app/helper.py     │──────► │ API ПриватБанку й monobank  │
│ виписки, файли, підказки ШІ    │        └─────────────────────────────┘
└──────────────────────────────┘
```

1. **Панель** працює в браузері, на сторінці CRM. Вона користується входом самого користувача. Сервера в проєкту немає.
2. **«Помічник»** — маленька програма на Python на комп'ютері бухгалтера. Вона бере виписки з банків і зберігає резервні копії та журнали.
3. **Правила** — один файл `rules/rules.json`. Його читає і панель, і Помічник.

## Чому так

- **Закладка, а не розширення чи окремий сайт.** Нічого не треба встановлювати в браузер. Панель бачить CRM так само, як користувач, і не має більше прав, ніж він.
- **Токени банків не виходять з комп'ютера.** Помічник слухає лише `127.0.0.1` і приймає запити лише зі сторінки CRM.
- **Логіка окремо від сторінки.** Усе в `core/` працює без браузера. Тому його можна перевірити сотнями швидких тестів.
- **Правила — це дані, а не код.** Бухгалтер може прочитати правило і зрозуміти, чому запис позначено.

## Папка `core/` — логіка

| Файл | Що робить |
|---|---|
| `rules-engine.js` | Читає `rules.json`, перевіряє його на помилки, застосовує правила до запису. Пріоритети, винятки, дати дії правил. |
| `crm-model.js` | Описує, як CRM зберігає запис кешфлоу. Перетворює запис у зручний вигляд і назад. Перевіряє права користувача. |
| `linter.js` | Перевірка статей і проєктів. План змін, резервна копія, застосування по одному запису, перевірка після зміни, відкат. Обмеження частоти запитів. |
| `recon.js` | Звірка з банком. Докладно — у [RECONCILIATION.md](RECONCILIATION.md). |
| `matching.js` | Зіставлення виплат банку з погодженнями. Наприклад, пакет зарплати на кілька карток = погодження кількох людей. |
| `withdrawals.js` | Виплати менеджерам проти погоджень: людина, тімлід, команда; схожі прізвища й описки. |
| `drafts.js` | Чернетки CRM: новий запис спершу стає чернеткою, проводить його людина. |
| `xlsx.js` | Звіт у файл Excel без сторонніх бібліотек. |

Кожен файл можна підключити і в браузері, і в Node.js. Зовнішніх залежностей немає.

## Папка `ui/` — панель

- `linter-panel.js` — рамка панелі, вкладка «Статті й проєкти».
- `bank-panel/NN-….part.js` — вкладка «Звірка з банком». Це один великий модуль, розрізаний на 12 частин за розділами. Збірка склеює їх за номерами.
- `approvals-tab.js` — допоміжна логіка вкладки «Погодження». У публічній версії сама вкладка схована (вона вбудовує сторонню програму).
- `combo.js` — список з пошуком.

Панель не користується бібліотеками. Це звичайний JavaScript і HTML.

## Закладка й підпис

- `bookmarklet/loader.js` — те, що лежить у закладці. Він бере код панелі з Помічника або зі збереженої копії в браузері.
- Код панелі підписано (ECDSA P-256). Завантажувач виконує лише код з правильним підписом. Так чужий або змінений файл не запуститься на сторінці CRM.
- `bookmarklet/main.js` — запуск панелі: перевірка сайту, вхід, з'єднання з Помічником.
- Підпис без сторонніх пакетів є і на Python (`build/sign.py`), і в Node. Тест перевіряє, що вони розуміють одне одного.

## Збірка

`build/build.js` (Node) і `build/build.py` (Python) роблять те саме: склеюють `core/`, `ui/`, правила й запуск в один файл `dist/cashflow_linter.js` і підписують його. Два збирачі потрібні, бо в колег може не бути Node. Тест `build-parity.test.js` перевіряє, що обидва дають однаковий файл.

`build/build-demo.js` робить збірку для демо-сторінки: без підпису, з перевіркою «це демо» замість перевірки сайту.

## «Помічник» — `app/`

- `helper.py` — локальний веб-сервер на стандартній бібліотеці Python. Вікно в браузері, запуск `privat_fetch.py`, зберігання токена CRM (зашифровано засобами Windows), редактор правил.
- `helper_ai.py` — підказки ШІ для записів, яких не покриває жодне правило. Номери рахунків, карток і телефони перед відправкою приховуються. Є місячний ліміт витрат. Вирішує завжди людина.
- `install/bank/privat_fetch.py` — виписки з API ПриватБанку й monobank у файл JSON. Перевіряє, що вхідний залишок плюс рух дорівнює вихідному, і перепитує банк, якщо ні.

## Безпека змін

1. За замовчуванням панель лише показує. Режим змін вмикається окремою закладкою.
2. Нічого не позначено заздалегідь. Кожну зміну вибирає людина.
3. Перед зміною запис зберігається як був. Після зміни він читається з CRM і порівнюється.
4. Лінтер змінює лише статтю, проєкт і тип запису. Суму, дату й рахунок — ніколи.
5. Нові записи йдуть у чернетки. Проводить їх людина в CRM.
6. Є журнал: що було, що стало, що відповів CRM.

## Тести

- `test/*.test.js` — 514 тестів на вбудованому в Node засобі `node:test`. Без сторонніх пакетів.
- `test/test_*.py` — 93 тести на `unittest`.
- `test/lib/panel-harness.js` — імітація сторінки: панель «Звірка з банком» запускається цілком, без браузера.
- `test/mock_crm_server.py` — імітація CRM і Помічника для ручної перевірки закладки в браузері.
- `test/fake_anthropic.py` — підробний клієнт ШІ: тести не ходять у мережу й нічого не коштують.
- `test/rule-cases.json` — приклади коментарів для кожного правила: де воно має спрацювати, а де ні.

Правило проєкту: кожна нова поведінка приходить з тестом, який падає на старому коді.
